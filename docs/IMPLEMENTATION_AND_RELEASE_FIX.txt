CHANGES VERIFIED
- Dashboard and emails show the configured server name for affected servers and
  alert senders. Existing historical event displays also follow server renames.
  Immutable membership keys remain internal; no certificate rotation is needed.
- Installation, dashboard changes and command-line reset accept passwords without
  a minimum length, including empty strings (maximum 256 characters). Hashing,
  authentication, session expiry, login throttling and CSRF checks remain in use.
- Two configurable brand identities appear on opposite sides of the header.
  The supplied AIVID SVG is bundled; email uses an embedded PNG copy.
  Custom PNG/JPEG/WebP logos are resized in-browser, capped at 256 KB per logo,
  and stored with replicated settings. Vendor reset and customer removal work.
- Offline, recovery, resource and test subjects are individually editable, as are
  email heading, body, footer and accent color. Templates use an allowlist of
  literal placeholders. Values are HTML-escaped and mail header injection is
  rejected. Messages contain HTML, a plain-text alternative and embedded logos.
- Email preview renders the draft in a sandboxed iframe without queueing mail.
  Subjects, server names, logos and settings survive restart and sender failover.
- Legacy SMTP/threshold settings gain presentation defaults without mutating
  the durable record on reads. Legacy local logos up to 256 KB migrate once;
  restoring the default remains effective after saving.
- All product communication uses a single HTTPS listener on TCP 8282. SMTP is
  outbound to the chosen relay. No additional internal monitor port was added.

LIVE FAILURE TESTS
Both explicit priorities and blank/automatic registration order were tested with
three independent HTTPS processes, SQLite databases and a local SMTP capture relay.
For the automatic run, all three nodes were installed from the signed offline
release before starting the acceptance tests.

Server 1 stopped: server 2 became sender and submitted exactly one offline alert;
server 3 remained standby. Custom subject, human-readable names and both embedded
logos were verified in the captured MIME message. Outage/recovery, CPU critical
and recovery, partitions, rejoining, sender death during SMTP DATA, and majority
loss were exercised. Each run accepted 11 distinct SMTP Message-IDs. An ambiguous
send became uncertain instead of being automatically resent. No real recipients
were contacted.
